# Task: QA, testing end-to-end y despliegue

## Description
Ejecutar pruebas end-to-end de todos los flujos del sistema, corregir errores encontrados, y preparar la documentación operativa para que el médico pueda administrar el sistema de forma autónoma. Incluye el pase a producción con credenciales reales de la pasarela de pago.

## Acceptance Criteria

**Testing de flujos principales:**
- [ ] Flujo completo de agendamiento: formulario → pago sandbox → confirmación email → evento Calendar con Meet link
- [ ] Flujo de cancelación paciente con ≥ 24h: token válido → política visible → cancelación → emails → slot liberado en Calendar
- [ ] Flujo de cancelación paciente con < 24h: mensaje bloqueante correcto, sin cancelación
- [ ] Flujo de cancelación médico: médico elimina evento en Calendar → paciente recibe email con opciones
- [ ] Flujo de recordatorio: crear cita con fecha en ~25h → verificar que el trigger envía el recordatorio en el siguiente run horario
- [ ] Flujo de pago rechazado: webhook con estado rechazado → Sheets actualizado → sin email de confirmación

**Verificaciones de seguridad:**
- [ ] Token de cancelación no puede reutilizarse tras haber sido usado
- [ ] Token inválido o inexistente muestra error apropiado sin exponer información del sistema
- [ ] El webhook de pago valida la firma de la pasarela (no acepta POST de terceros)
- [ ] Google Sheets no es accesible públicamente (solo el médico tiene acceso)

**Verificaciones de rendimiento:**
- [ ] Email de confirmación enviado en < 2 minutos post-pago (medido en sandbox)
- [ ] Página de agendamiento carga en < 3 segundos

**Pase a producción:**
- [ ] Cambiar credenciales de pasarela de modo sandbox a modo producción en Config.gs / Script Properties
- [ ] Web App de Apps Script desplegada como versión de producción
- [ ] URL final del Web App configurada en Config.gs (HORAS_MIN_CANCELACION, URL_WEB_APP, etc.)
- [ ] Trigger horario de recordatorios activo y verificado

**Documentación operativa para el médico:**
- [ ] Guía de uso: cómo configurar disponibilidad en Google Calendar
- [ ] Guía de uso: cómo ver las citas del día/semana en Google Sheets
- [ ] Guía de uso: cómo crear el informe post-consulta con el template
- [ ] Qué hacer si un paciente reporta que no recibió el email de confirmación (proceso manual de backup)
- [ ] Cómo gestionar un reembolso manualmente en la pasarela
- [ ] Límites de la plataforma: cuota de emails, límites de Apps Script

## Technical Details
- Usar modo sandbox de la pasarela para todos los tests previos a producción
- Los logs de ejecución de Apps Script están disponibles en View → Executions del editor
- Verificar en Google Calendar que los eventos se crean correctamente con el link de Meet
- Para testear el trigger horario sin esperar 1 hora: ejecutar `enviarRecordatoriosHorarios()` manualmente con una cita de prueba en la ventana correcta
- Archivos afectados: Config.gs (cambio de credenciales), documentación operativa (Google Doc o README)
